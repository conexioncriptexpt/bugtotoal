## Root cause
The deployment was stopped by the platform's automated phishing/abuse classification gate, BEFORE any build, image, secret, or deploy step ran. The most recent failed run confirms the same block at the classification stage:

```
await_phishing: activity error (... v3.InitialDeploy.AwaitPhishingClassification ...):
deployment blocked: there has been an error with this deployment.
Please fork the session and start a new deployment
(type: wrapError): deployment blocked
```

Both signals point to one cause: a server-side, non-retryable block (`deployment_blocked` / `AwaitPhishingClassification`). This is a policy/security decision, not a code, dependency, manifest, secret, tier, or infrastructure-capacity fault.

## Why no fix was applied here
There is nothing in the app source, manifest set, secrets, tier, or DNS that influences a phishing-classification block. The trigger is explicitly `retryable: false`. Re-firing `resume_pipeline` would deterministically return the same 409, so it was not attempted. This must be cleared on the Emergent side.

- Only the new redeploy is blocked from going live.
